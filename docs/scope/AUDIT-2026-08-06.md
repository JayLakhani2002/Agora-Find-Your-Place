## 2. What is genuinely strong

Verified, not asserted:

- **Test suite is real.** 615 passing / 10 skipped across 6 packages in 15.3s. `@agora/legal` alone carries 374 tests.
- **CI enforces meaningful gates** (`.github/workflows/ci.yml`): typecheck, biome lint, tests, build, migration validation, **gitleaks full-history secret scan**, and a bespoke **`sql.raw` reintroduction check**. That last one is a zero-regression guard most teams never write.
- **Cost control precedes billing.** `apps/web/src/server/lib/rate-limit.ts` defines fail-closed AI limits (6/min, 120/day) enforced in `aiProcedure` before any Bedrock call, independent of the billing flag. `deck.getDeck` can fan out to 30 model calls, and the limiter is sized for it.
- **GDPR cascade deletes are actually modelled.** All 9 tables carry explicit FK cascade or SET NULL (`packages/db/src/schema.ts`).
- **EU residency is enforced in IAM, not just intent.** `infrastructure/AgoraBedrockWorker-invoke-policy.json:5` carries an explicit `DenyAnyBedrockCallOutsideTheEU` statement.
- **The matching pipeline is not keyword search** (Goal 7 is largely already met): SQL legal filter → vector cosine over HNSW → pg_trgm keyword → Haiku LLM rerank, with a hard latency budget and graceful degradation (`apps/web/src/server/routers/deck.ts`).

## 3. Critical findings

### 3.1 — Document generation has been broken since June (SEV-1) — ROOT CAUSE CONFIRMED
`docs/Database/INPUTS-NEEDED-FROM-JAY.md` §5.1 recorded every generation failing. Probed directly against the live account on 2026-08-06:

> `ResourceNotFoundException: Model use case details have not been submitted for this account. Fill out the Anthropic use case details form before using the model.`

**The brief's premise was correct — the website genuinely is the Bedrock gate.** The Anthropic use-case form is reviewed against the company site. `infrastructure/bedrock-use-case.json` holds prepared text that was never successfully submitted or approved. The Bedrock client itself is correctly written; the account simply has no model access.

Two latent failures sat behind it and are **now fixed**:
1. `.env.example` shipped bare `anthropic.*` ids. Verified rejection: *"Invocation of model ID … with on-demand throughput isn't supported. Retry with the ID or ARN of an inference profile."* Claude 4.5-class models are inference-profile-only. Corrected to `eu.` prefix.
2. `resolveModelId` accepted bare ids silently — which is *why* this stayed invisible for two months: it failed at invoke time as a user-facing 500, never at boot. It now throws at resolve time naming the corrected id (`packages/ai/src/bedrock/claude.ts` + 4 regression tests in `packages/ai/tests/model-id.test.ts`).

Remaining action is Jay's: resubmit the use-case form, sequenced *after* the Q1 positioning rewrite so the reviewed site matches the submitted text.

The IAM policy is sound — it already carries the `inference-profile/eu.anthropic.claude-*` ARN and foundation-model ARNs across all six EU regions.

### 3.2 — Security controls are built but not switched on
| Control | Built | Active |
|---|---|---|
| RLS (migrations 0006/0007, `withUserContext`, 5 tests, runbook) | ✅ | ❌ **zero call sites in `apps/web`** |
| KMS field encryption (`resumes.content`, 12 tests, backfill script) | ✅ | ❌ flag OFF, no KMS key exists |

`withUserContext` is referenced only by its own definition, its barrel export, and its tests. Every live query still uses stateless `getDb()`. Tenant isolation today is **application-layer only**.

⚠️ Migration `0007` is fail-closed. Applying it before wiring `withUserContext` will break every user-scoped query.

### 3.3 — GDPR Article 20 (data portability) is not implemented
`apps/web/src/server/routers/gdpr.ts` exposes exactly one procedure: `deleteAccount`. Erasure (Art. 17) works. Export does not exist. For an explicitly GDPR-first EU product this is a compliance gap, and it is table stakes for the Goal 5 parity claim.

### 3.4 — Pricing model contradicts itself three ways
| Source | Model |
|---|---|
| `packages/billing/src/stripe.ts:56-76` (**shipped code**) | Free / Pro **€9 per month subscription** |
| `CLAUDE.md` | Credit-based pay-as-you-go, prices **TBD** |
| `docs/scope/PROJECT-SCOPE.md:199` | Credits **decided** — €19/100 · €39/250 · €79/600 |

Zero occurrences of "credit" in the billing package. The code implements a model two documents say was replaced.

### 3.5 — Positioning contradicts the stated audience goal
40+ Berlin/student/visa references across `apps/website`, and the Germany block (`src/content/en.ts:181-240`) is deliberately built as the moat — §16b hour caps, the 140-day rule, Werkstudent vs Minijob thresholds, Chancenkarte, Blue Card, Ausländerbehörde notification timing. Site copy states "Built for Germany, in English" (`en.ts:478`).

This is backed by working code (`allowedVisaTypes` SQL filtering, `@agora/legal`, visa regression tests), so it is a real asset, not just copy. See DECISIONS-NEEDED.md Q1 — this is the highest-leverage open decision in the project.

### 3.6 — The AWS Bedrock use-case submission encodes the old positioning
`infrastructure/bedrock-use-case.json` tells AWS: *"Agora helps international students in Germany find part-time work"*, and points reviewers at `joinagora.eu`. If the site pivots global without resubmitting, the reviewed site contradicts the application — an avoidable rejection risk.

### 3.7 — Repository is a single point of failure
172 uncommitted files (64 untracked) and **4 commits never pushed** to `origin` (`Agora-Find-Your-Place`), including the Bedrock IAM policy work. All of it exists only on one machine.

### 3.8 — Accepted dependency risk
`pnpm audit`: 18 vulnerabilities — 1 low, 12 moderate, **5 high** (serialize-javascript RCE, vite `server.fs.deny` bypass, 3× brace-expansion DoS) via `next-pwa` and `crawlee`. CI intentionally treats high as non-blocking since none are runtime paths. Defensible, but it is an accepted risk rather than a clean bill.
